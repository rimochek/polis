# Repository conventions

## Placement

Keep workspace UI in `src/`, API modules in `server/`, and shared domain contracts in `shared/`. Keep the independent landing in `landing/`; its `public/` directory is the publication asset boundary. Put tests in `tests/` and operational scripts in the appropriate `scripts/` subdirectory. Add explanatory documentation under `docs/`, design specifications under `docs/design/`, and deployment history under `docs/deployment/`. Runtime Nginx files and EC2 instructions live together in `deploy/`.

Root configuration files stay at the root because npm, Vite, TypeScript, Docker, and Compose consume them there. `.github/` belongs to GitHub Actions and `.impeccable/` belongs to the design tooling. Preserve migration directory names and applied SQL: they are database history, not files to rename during cleanup.

## Generated and local files

- `package-lock.json` is the authoritative npm lockfile. Install with `npm ci`; update dependencies with npm.
- `landing/src/demo-data.json`, `landing/demo.html`, the three demo PDFs, and the landing favicon are regenerated by `npm run prepare:landing`. Commit intentional fixture changes together; PDF metadata can differ between builds.
- The image and its provenance JSON are source assets. Publication strips the provenance sidecar.
- `node_modules/`, `dist/`, `landing/dist/`, `data/`, `artifacts/`, `output/`, and `outputs/` are local/generated. Do not hand-format dependencies, binary assets, or output bundles.
- Environment files contain local configuration and remain ignored; `.env.example` documents variable names.

## Style and checks

Prettier formats TypeScript, JavaScript, TSX, CSS, HTML, JSON, YAML, and Markdown. Use `npm run format` and commit the result. `.editorconfig` defines UTF-8, LF, final newlines, and indentation. Prisma uses `npm run db:format`; applied migrations retain their original SQL. The optional Python presentation generator uses Black (see `scripts/README.md`). PowerShell and Nginx files use readable manual formatting.

Write code comments in English. Explain constraints, ownership, side effects, and non-obvious behavior; avoid narrating obvious assignments. Product copy and synthetic insurance documents remain in Russian. Keep formatting and organization changes behavior-preserving.

Before submitting: run formatting checks, tests, and both builds. Build-generated fixture churn is not a source change unless fixture updates are intended.
