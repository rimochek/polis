# Polis workspace concept

Mode: Operate. Code-led extension of the established Polis visual system; user requests an approximate interactive structure, not production chat or deployment. Taste is scoped to applicable brief inference only (its full landing workflow does not apply to dashboards). Airtable community reference supplies restrained typography and separators through the existing DESIGN.md.

THESIS: A client owns multiple task-specific cases. Each case holds typed/versioned documents, client requirements, evidence-backed findings, open questions, a reviewed report and activity. Contextual chat supports the case; workspace chat handles navigation/status. Neither chat silently alters reviewed findings.

VISITOR AND JOB: A Kazakhstan broker needs to know what requires attention, verify evidence, prepare clarifications and a client report. All sample data is fictional. Demo chat is explicitly canned, uploads store names in memory only. Real production application stays at /; concept at /concept.html.

WORLD: Inherit DESIGN.md's Golos Text, green charcoal navigation, teal actions, white document surfaces, fine separators and compact controls. No new global tokens or identity changes.

FIRST VIEWPORT: Persistent left navigation, case heading and lifecycle, central findings and requirements, contextual chat on the right. Signature interaction: finding or chat citation opens the source fragment; user can move into comparison, mark demo review and download the sample report. The case assistant is a full viewport-height right panel with independent message scrolling and a bottom composer; it reserves space across the whole page on desktop. At 900px and below it replaces the visible workspace while open, and starts closed on a fresh mobile visit. Closing or Escape returns focus to the toggle.

BEHAVIOR: Case list/search/filter, client-to-case navigation, empty/new-case flow, document role assignment, deterministic chat and explicit unknown replies, clarification checkboxes and draft copying, gated report export, source dialog and history. No API calls, credential use, emails, production record edits or deployment.

FINISH: Desktop/mobile browser inspection and interaction verification, bounded correction; independent finish review and documentation comparison per Impeccable. Preserve incumbent DESIGN.md and design.json. Pre-existing PRODUCT.md statement about no real credentials is stale relative to prior Google setup; no unrelated repair.
