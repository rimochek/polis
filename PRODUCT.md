# Product

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Implementation choice delegated by the user's instruction to begin: React, TypeScript, Vite and a local Node HTTP API. A local first prototype keeps operation inspectable without paid hosting.

## Users
Insurance brokers in Kazakhstan preparing commercial property insurance proposals for business clients. The founder evaluates a working first version.

## Product Purpose
Reduce active broker time from insurer documents to a checked customer proposal. The proposed pilot target is 30% less active time across ten cases, not a proven claim.

## Operating Context
Client requirements, multiple insurer PDFs, comparisons, clarifications, updated proposals and broker review. Russian UI; prices displayed in tenge when documents specify KZT.

## Capabilities and Constraints
User selected an interactive demonstration plus real AI analysis of uploaded PDFs when an API key is configured. Include evidence citations, editable comparisons, clarification questions, version changes and a printable customer proposal. No production multi-tenant or insurance issuance claim. No external messages are sent by this prototype.

## Evidence on Hand
No real insurer documents or API credentials supplied. All bundled examples must be visibly synthetic and use fictional insurer names. Market demand and model accuracy remain unverified.

## Product Principles
Human review before final export. Missing evidence remains explicit. Source material is untrusted data. Demo and real analysis are clearly distinguished. Never silently replace a failed real analysis with fabricated results.

## Open Decisions / Implementation Assumptions
Working name: Polis. First line: commercial property. Working broker application retains local persistence. The user subsequently requested a public landing on Vercel; its static demonstration contains only synthetic documents and transient browser state. Real uploads and AI analysis remain in the local application. Code-led construction inferred from the request to build; not recorded as the user's standing workflow preference.
